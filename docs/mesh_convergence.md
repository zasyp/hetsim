# Сходимость по сетке для FEM-магнитостатики

Пункт 3 из «Части IV» лекции: `amr_passes=4` было подобрано на глаз. Здесь —
что получилось, когда это проверили численно, и две вещи, которые всплыли
попутно и оказались важнее самого ответа.

Запуск: `python -m src.examples.mesh_convergence`

---

## 1. Что вообще можно спрашивать у этой задачи

Кромка полюса — входящий угол железа. У точного решения там `|B| ~ ρ^(−1/3)`,
то есть **поточечный максимум поля не сходится по определению**: он растёт с
измельчением без предела. Любая «проверка сходимости», построенная на
`max|B_r|`, будет вечно рапортовать провал, и это не про качество сетки.

Поэтому мерим интегральные (и удалённые от сингулярности) функционалы:

| метрика | что это | почему честная |
|---------|---------|----------------|
| `flux_exit` | поток через кольцо среза, `2π·Δψ` | прямо из узлового `ψ`, без дифференцирования |
| `Br_int` | `∫|B_r| dz` по средней линии | интеграл; на этом профиле живёт 1D-модель электронов |
| `Br_peak`, `z_peak` | пик того же профиля и его положение | вне сингулярности |
| `W_roi` | энергия поля в плазменной области | интеграл по объёму |
| `Br_max_grid` | поточечный максимум на разрядной сетке | **контроль: должен расходиться** |

Всё считается на калиброванном поле (|B| в опорной точке = `B_target`), потому
что именно его видит плазменная модель. То есть метрики — это отношения формы к
`B_ref`, и глобальное перемасштабирование тока их не двигает.

## 2. Ответ по `amr_passes`

Базовая сетка 121×221, `amr_frac=0.05`. Относительное изменение от прохода к
проходу:

```
  pass      flux_exit       Br_int      Br_peak       z_peak        W_roi  Br_max_grid
  0->1         0.143%       0.019%       0.040%       0.003%       0.053%       0.162%
  1->2         0.577%       0.030%       0.008%       0.002%       0.078%       2.616%
  2->3         0.080%       0.012%       0.011%       0.001%       0.023%       1.240%
  3->4         0.351%       0.014%       0.009%       0.001%       0.036%       7.985%
  4->5         0.012%       0.002%       0.001%       0.002%       0.002%      15.621%
  5->6         0.144%       0.009%       0.007%       0.001%       0.016%       8.620%
```

**Профильные метрики сходятся рано, поток — поздно.** `Br_int`, `Br_peak`,
`z_peak` и `W_roi` встают на 0.01–0.04% уже к проходу 2–3 и дальше не двигаются.
А вот поток через срез к четвёртому проходу ещё гуляет на 0.1–0.4% от прохода к
проходу и уходит ниже 0.01% только к проходам 10–13 (26741 → ~55000 узлов,
0.5 → 12 с). Это не дрейф к другому ответу — разброс знакопеременный, значения
болтаются вокруг 6.24 uWb, — а именно шум: каждый проход перекраивает элементы у
кромки полюса, и интеграл `ψ` по срезу это чувствует.

**Вывод по `amr_passes=4` держится**, но с честной формулировкой: он даёт ~0.01%
по профилю `B_r`, на котором живёт 1D-модель электронов, и ~0.4% по потоку через
срез. Для потока это по-прежнему на порядки лучше, чем заглушечные `n_e`/`n_n`.
Если поток когда-нибудь станет ведущей величиной — брать 10+ проходов.

(В первой версии этой таблицы поток выглядел спокойнее — 0.02% к проходу 4. Те
цифры покупались лишним измельчением из-за бага с переиспользованием `tid`, см.
§4.)

Контрольный столбец делает своё дело: `Br_max_grid` растёт 596 → 838 Гс
монотонно и не думает останавливаться (к проходу 14 — 2089 Гс). Отсюда
практический вывод:

> Пункт 3 в `fem_check.py` — это **не** физическое утверждение и не критерий
> качества. Число зависит от того, насколько мелко разрешена сингулярность.
> Считать его надо хотя бы по вакуумным узлам (там и живёт утечка FD через
> полюсную грань, 366 Гс против 320 Гс) — по всей сетке это просто «какое поле
> внутри наконечника». Как индикатор утечки оно работает, как величина — нет.

## 3. Побочная находка A: конформность ломается молча

Докстринг `triangulate_structured` обещает: «material boxes are aligned to
these grid lines, no triangle straddles a material boundary». Это верно **только
для сетки 121×221**.

`OUTER_POLE` начинается на `r = 35.5 мм`. При `nr = 61` (`dr = 1 мм`) и
`nr = 181` (`dr = 0.333 мм`) эта координата попадает ровно между линиями сетки,
и материал, назначаемый по центроиду треугольника, сдвигает грань полюса на
`dr/2`. Первый прогон sweep'а по базовой сетке выглядел так:

```
  base  61x111:  flux= 6.0383 uWb   Br_peak= 155.96 G     <- геометрия сдвинута
  base 121x221:  flux= 6.3199 uWb   Br_peak= 159.84 G
  base 181x331:  flux= 6.2289 uWb   Br_peak= 158.50 G     <- геометрия сдвинута
```

— немонотонно, разброс 4.7%. Это измерялась не сходимость дискретизации, а
**меняющаяся геометрия**.

Добавлено: `spt70_system.check_conformal(r, z)` — возвращает список рёбер
материалов, не лежащих на линиях сетки. `sweep_base` теперь такие сетки
пропускает. Допустимые разрешения: `nr = 120k+1`, `nz = 110k+1`.

## 4. Побочная находка B: калибровка бралась в ближайшем узле

Опорная точка `REFERENCE_POINT = (26.25 мм, 45 мм)` **не является узлом** при
`nr = 121` (26.25 / 0.5 = 52.5) и при `nr = 361`. Старый код брал
`argmin` по расстоянию, то есть считал калибровку в узле, отстоящем до `dr/2` от
геометрической опорной точки — и место калибровки прыгало вместе с сеткой.
Поскольку на этот `B_ref` делится **всё** поле, получался мешезависимый
пересчёт масштаба ~1%, который полностью маскировал реальную ошибку
дискретизации:

```
  до фикса   (ближайший узел):  121x221 → 241x441 :  flux −1.30%, Br_int −1.26%, Br_peak −1.29%
  после      (интерполяция)  :  121x221 → 241x441 :  flux +0.005%, Br_int +0.046%, Br_peak +0.01%
```

Одинаковые −1.3% по всем метрикам — подпись общего множителя, а не физики.
Исправлено в `fem._sample_B_at`: `|B|` в опорной точке берётся кусочно-линейной
интерполяцией по вакуумным треугольникам (железо замаскировано), с откатом на
ближайший вакуумный узел, если точка вне сетки.

Сходимость по базовой сетке после фикса (все сетки конформные, `amr_passes=4`):

```
  base 121x221:  31793 узла    flux= 6.2498 uWb  Br_int=4458.38  Br_peak=157.77 G  z_peak=26.982 mm
  base 241x441: 124547 узлов   flux= 6.2432 uWb  Br_int=4459.97  Br_peak=157.78 G  z_peak=26.805 mm
  base 361x661: 277891 узел    flux= 6.2399 uWb  Br_int=4460.03  Br_peak=157.81 G  z_peak=26.852 mm
```

Разброс: поток 0.16%, `Br_int` 0.04%, `Br_peak` 0.03%, энергия 0.07%. Хуже всех
`z_peak` — 0.66% (0.18 мм), и это ожидаемо: максимум профиля плоский, парабола
по трём точкам на плоской вершине чувствительна.

Узлов стало примерно на 20% меньше, чем в первой версии этой таблицы (было
39609 / 156275 / 349890), и это не смена критерия отбора: `k` считается ровно от
того же числа элементов (на этой задаче у **всех** элементов ROI оценка строго
положительна, так что `cand.size == roi.sum()` до штуки). Разница — починенная
бисекция: раньше первый ребёнок наследовал `tid` родителя, индексы в `marked`
начинали указывать на уже разбитый элемент, и часть помеченных треугольников
резалась по второму разу. Те лишние элементы и покупали прежние 0.013% по
потоку. 0.16% — честная цена `amr_frac=0.05`; вывод ниже от этого не меняется.

**Итого по разрешению: базовая 121×221 + `amr_passes=4` даёт поле с точностью
~0.1% по интегральным величинам. Дальше измельчать бессмысленно — заглушечные
плотности `n_e`/`n_n` дают ошибку на порядки больше.**

## 5. Что изменилось в числах разряда

Фикс калибровки сдвигает поле примерно на 1.3%, поэтому решение проверено
до и после:

| | до (ближайший узел) | после (интерполяция) |
|---|---|---|
| `solve_spt70` | 38 итераций, пик Te 28.30 эВ | 38 итераций, пик Te 28.24 эВ |
| бюджет мощности, Вт | ohmic 481 / wall 32 / ioniz 29 / rad 11 | ohmic 488 / wall 32 / ioniz 29 / rad 11 |
| `voltage_sweep`, Te/V_d | 0.095 / 0.095 / 0.094 / 0.089 / 0.085 | 0.094 / 0.095 / 0.094 / 0.088 / 0.085 |

То есть все выводы лекции в силе, «правило 0.1» держится, сдвиг в пределах
0.2% по Te.

## 6. Изменения в коде

- `magnetics/fem.py` — `_sample_B_at()`, калибровка интерполяцией вместо
  ближайшего узла; плюс отдельный проход по восьми замечаниям к бисекции и
  восстановлению поля (`orient_ccw`, итеративный `_bisect` с новыми id для
  обоих детей, `mark_for_refinement`, `np.bincount` вместо `np.add.at`,
  `np.ma.filled` вместо `np.asarray` на маскированном результате, проверка
  опорной точки на попадание в железо, `B` из `ψ` конечными разностями на
  сетке разряда).
- `magnetics/spt70_system.py` — `material_edges()`, `check_conformal()`.
- `examples/mesh_convergence.py` — сам sweep, метрики, графики
  (`mesh_convergence.png`, `mesh_convergence_rates.png`).
- `examples/amr_marked_positions.py` — куда именно AMR кладёт элементы.
